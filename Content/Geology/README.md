# 行星地质预设

一颗行星的矿物分布定义在 **UDataAsset** 里：`Content/Geology/Planets/DA_Geology_<名字>`。
JSON 预设已退役（2026-10-25）。

## 怎么改

1. 选中 `DA_Geology_Earth`，在 Details 里调 `Elements`。
2. 选中行星 Actor，`Planet|Geology → Geology Asset` 指向这份资产。
   选中**矿物观测组件**时同一个槽也会出现（`Planet|MineralView → Geology Asset`），
   改哪边都一样：它是行星那份的镜像，不存盘。
3. 点 `重建行星（应用地质预设改动）` **重建行星** —— 体素是烘焙的，改预设不会自动重刷地表。
   （按钮在行星 Actor Details 的 `Planet|Geology` 分类里；这个名字是 C++ 里写死的中文
   DisplayName，英文面板也显示中文。）

想看矿囊长什么样：选中行星上的矿物组件 → Details 的 `Planet|MineralView` 分类里点
`Enter Mineral Preview In Editor`（这个按钮没有 DisplayName，标签由 C++ 函数名
`EnterMineralPreviewInEditor` 自动分词而来）。
退出点同分类的 `Exit Mineral Preview In Editor`，关卡不会变脏（编辑器预览只做临时隐藏）。

## 参数语义

每个元素有一组**分布生成器**（`Distributions`）。一个元素可以叠加多个生成器，
**逐点取 max**（不是相加）。四种形态：

| 生成器 | 形态 | 地球上的用法 |
|---|---|---|
| 囊状（球团） | 离散团块 | 旧资产的迁移目标；最朴素的形态 |
| 片层（透镜） | 沿切平面铺开的薄椭球 | 硅 |
| 脉状（穿切） | 折线骨架 + 胶囊 | 铁、铜 |
| 浸染（散布） | 大量小颗粒 | 钛、铀 |

公共参数（每个生成器各有一套）：

| 参数 | 含义 |
|---|---|
| `Seed` | 0 = 按「元素 Id + 生成器下标 + 类名」派生。**生成器重排会改变形状** |
| `ShapeDetail` | 一个特征尺度内几个噪声周期，越大越破碎 |
| `Octaves` / `Lacunarity` / `Gain` | 分形噪声的层数与衰减 |
| `VeinThreshold` | 噪声稀疏阈值，越高越破碎；0 = 不稀疏 |

`Abundance` 在元素上，**只影响颜色混合与图例占比**，不改几何。

**想看不同元素互相穿插**：给同一深度带上的两个元素各挂一个生成器，把它们的
`DepthCenter` / `DepthBias` 调到同一区间即可 —— 几何是否重叠由生成器决定，
`Abundance` 帮不上忙。

## 观测视图与生成器的关系

观测视图的 `CellsPerFeature` 跟的是生成器的**特征尺度**（片层=全厚、脉=管直径、
浸染=粒径、囊=囊直径），不是行星直径：换一颗大行星，相对清晰度不变。

**分簇按元素分开做。** 元素之间互不参与求值，所以每个元素的矿体只在它自己的区域里
找邻近伙伴、各用一套栅格。别指望「某个元素的包围盒大」会拖慢别的元素 —— 反过来也
一样，一个元素的颗粒再小，也只压缩它自己的格边。（早先的实现跨元素分簇，地球预设
因此每个任务都撞满 8'000'000 角点上限，进入观测视图要 20 秒以上。）

**空块不求值。** 每个任务的栅格按 8³ 格切块，只有与本簇区域包围盒相交的块逐点求值，
其余块直接留 0 —— 依据是每个分布的零支持域都落在它报出的 `Region.Bounds` 之内，
所以这只省时间、不改网格。片层这种「盒子大、实体薄」的形态因此在观测视图里也很快。

- `ShapeDetail` 要能被观测视图解析，需 `ShapeDetail ≤ CellsPerFeature / 2`
  （默认 3 ≤ 6）。
- 片层宽而薄是刻意的：厚度减半，该元素的观测视图角点涨约 4 倍（单任务超过
  8'000'000 角点后会被降采样，涨势会停在那个上限附近，代价变成「更糊」）。
  建议厚度 ≥ 0.008、`CellsPerFeature` 取 12–16。
- 浸染想更密，先加粒径（角点 ∝ 粒径²），再加数量。
- 进入观测视图时日志会打三行：求值角点数 / 每元素矿体、`(元素,簇)` 任务数与撞上限
  的任务数、求值与抽面的耗时。`约 N 核并行` 接近 1 说明并行度被单个大任务卡死了。

## 旧资产

只有 `PodCount` 等遗留字段、没有生成器的资产，在运行期按原样建囊（种子用旧公式，
形状逐位不变）。资产**加载时**（`PostLoad`）会就地补一个等价的囊状生成器并把
`PodCount` 置 0；这一步不会把包标脏，所以磁盘上的数据要等你因为别的原因保存这份
资产时才会跟着变。行为前后一致，不用刻意去促成迁移。

遗留字段标了 `DeprecatedProperty`，新内容请一律用生成器。

## 数值约束

地表几何的 `GetSurfaceRadiusVoxels` 是不动点迭代，收敛因子约为

    GeometryAmplitude · √2 / (簇内最小特征半径 · 行星半径的体素数)

特征半径按生成器形态取：片层取半厚、脉取管半径、浸染取粒半径、囊取囊半径。
注意这一节用的是**半径**口径（`Region.CharacteristicRadius`），与上面「观测视图」一节的
`CellsPerFeature`（按**全厚**切格，`CellSize = 2·MinRadiusCm/CellsPerFeature`）不是同一个量。
因子明显小于 1 收敛干净；大于 1 会发散 —— 症状是「脚下的地面与看见的表面差几体素」，
不是崩溃。所以调高 `GeometryAmplitude` 时，要同时看一眼这颗行星上**最小**的那个
特征半径。

## 已知缺口：同元素相邻簇的盒边截断

观测视图在**同一元素内**按区域的空间邻近关系分簇，每簇一套局部栅格。簇之间只保证
AABB 不相交，**不保证相隔一格**：同一元素、两簇距离小于一格且半径差很大时，对方的
区域会落进本簇盒子的一格余量里，等值面在盒边被截断（看起来像面上有缺口）。默认
数值下罕见，但把某个元素的生成器数量或密度调大（簇更多）、或把某个生成器的特征
半径调小（格边更细），碰到它的概率会上升 —— 调参后看到面有缺口，先怀疑这里，
而不是材质。

稀疏块的判据（「块外恒为 0」）只对**本簇**的区域成立，对外来簇同样不设防：外来
矿体若落进被跳过的空块，那一块就整块不出面。这与上面是同一个缺口，只是表现得更早
一点（盒子内部而不是盒边）。
