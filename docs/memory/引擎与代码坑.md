# 引擎与代码坑

## 体素（VoxelFree）

- `TVoxelGeneratorInstanceHelper<TInstance, UWorldObject>` 的 `UWorldObject` 会作为 `TSubclassOf<UVoxelGenerator>` 传给 `FVoxelGeneratorInstance`，构造期 `checkf` 它派生自 `UVoxelGenerator`（`VoxelGeneratorHelpers.h:45`、`VoxelGeneratorInstance.h:59`；`:55` 有一行注释掉的 `static_assert` 写着这条契约）。基于 `UDataAsset` 的生成器**不能**把自己填进去，运行期当场 checkf。模板第二参数填 `UVoxelPlanetGenerator` 适配器，宿主指针传 `nullptr` 是安全的：`Class`/`Object` 只用于序列化，`FVoxelGeneratorPicker` 只存 `TSubclassOf`/`TObjectPtr`、每次建世界重调 `GetInstance()`。
- VoxelFree 编辑器模块没有 `UVoxelGenerator` 的 `UFactory`（生成器资产由未安装的 VoxelGraph 插件提供），所以本项目的生成器预设只能做成 `UDataAsset`（走标准「Miscellaneous > Data Asset」创建），这反过来锁死了上面的模板参数选择。
- `UVoxelGenerator::GetParameters()`（`VoxelGenerator.cpp:18-63`）枚举子类每个 `CPF_Edit` 且非 `CPF_EditConst` 的属性，交给 `FVoxelGeneratorParameterType` 构造（`VoxelGeneratorParameters.cpp:98-178`）——只认 `Float / Int / Bool / Object / SoftObject / Struct / Array / Set / Map`，其余（`FString=FStrProperty`、`FName`、`FText`、`FByteProperty`…）落到 `ensureMsgf(false, "Property: %s")`。
- 上述 ensure 的触发点不是生成器 Details，而是选中 `AVoxelWorld` 时它的 `FVoxelGeneratorPicker`：`VoxelGeneratorPickerCustomization.cpp:154-188` 会对生成器调 `GetParameters()`，每次点选都弹。2026-10-24 就是给生成器加 `GeologyPreset`（FString + EditAnywhere）炸的。修法：需要字符串字段就改成 `UPROPERTY(VisibleAnywhere, BlueprintReadWrite)`（即 `CPF_EditConst`，被跳过），作者入口放 Actor 上（本例 `AVoxelPlanetActor::GeologyPreset`）。`meta=(HideInGenerator)` 救不了——过滤在 `GetParameters` 之后（`:187`）。守门测试 `StellarEra.Planet.Geology.GeneratorParametersSupported`（`PlanetGeologyFieldTests.cpp`）。
- 渲染八叉树有**两条独立**细分路径，块数各按自己盒子体积涨，都不看盒子里有没有地形：① LOD —— `FVoxelRenderOctree::ShouldSubdivideByDistance`，与 ±`LODRange` 盒子相交的块细到 `LODToSet`，叶块边长 `32 · 2^LODToSet` 体素；② 碰撞 —— `ShouldSubdivideByOthers → IsInvokerInRange`，与 ±`CollisionsRange` 盒子相交的块**一路细到 `Height 0`，完全不经过 `LODToSet`**。第三条 `ShouldSubdivideByNeighbors` 只管 2:1 平衡，自动生成过渡环。
- `CollisionsRange` 是块数大头，不能跟 `LODRange` 一起放大。插件的报错（"reduce invokers distances / increase Max LOD"）和 `LODToSet` 都是诱饵：2026-10-18 只把 `LODToSet` 0→1，实测毫无效果，越界的是碰撞路径。
- 插件 1e6 上限不是有用护栏，真正上限是显存；它超限只把整棵树作废（`FVoxelDefaultLODManager::Tick` 仅在新树有效时替换 → 静默失效、地形 LOD 冻结）。2026-10-18 把 `CollisionsRange` 收到 6e4 让八叉树通过后，请求约 3.3e5 个区块，GTX 1650（4 GB）报「Video memory has been exhausted (52,945 MB over budget)」，整片渲染不出。范围要按显存反推；调参后看 HUD `Total tasks remaining`，几万要警惕，几十万必炸。
- `LODToSet` 每加一档，叶块边长翻倍、块数少 8 倍（「覆盖半径」与「网格精度」在固定块数下互换，本关体素 100 cm）：`LODToSet` 0/1/2 → 网格采样步长 1/2/4 米、覆盖半径约 240/480/960 米。`LODToSet = 1` 会让网格采样步长翻倍（`VoxelMesherUtilities`：`Step = 1 << LOD`），不是「画质不变」。碰撞路径逼出的 `Height 0` 块不参与渲染（`bChildrenVisible = false`），只买碰撞精度。
- `PredictionTime` 与两个范围同属一组参数：调用器位置 = 组件位置 + 速度 × `PredictionTime`，所以每个范围都要 ≥ 最大速度 × `PredictionTime`，否则飞船落在盒子外、碰撞直接消失（不是变粗）。
- 进/出星图（按 M）时报的 `VoxelDefaultRenderer.cpp:1249 / 846 / 302` ensure，根因是 `ToggleStarMap` 的 `Possess`：插件 `IsLocalInvoker` 只认被本地控制器 Possess 的 Pawn，换人时飞船/角色调用器 `bUseForLOD` 由真翻假，`FVoxelDefaultLODManager::UpdateInvokers` 置 `bNeedUpdate` 全量重建八叉树，与在飞 chunk 任务竞争。不是相机平滑不够慢（按 M 后 ~113 ms 就报，相机几乎没动）。修法：`Source/StellarEraCelestial/Planet/Src/Invokers/AlwaysLocalVoxelInvokerComponent.h` 覆写 `IsLocalInvoker_Implementation()` 恒返回 true（Simple 与 WithPrediction 各一子类），三处默认子对象都换成它。再遇同类 ensure 先查是否新 Possess 或调用器增删。
- 本工程 `FVoxelValue` 是 `TVoxelValueImpl<int16>`（`EIGHT_BITS_VOXEL_VALUE` 为 0），取值 `[-32767, 32767]`，`Full() = -32767`、`Empty() = +32767`。给体素比对测试造种子若按 8 位 ±127，半径 0.5 的球表面值 `round(0.1275 × 32767) ≈ -4178`，挖的合并是 `max`，±127 旧值都比它「空」→ 一格不变，逐格比对「一致」假通过。种子必须由 `FVoxelValue::MAX_VOXELVALUE` 派生（`% (2*Max+1) - Max`，避开 `-Max-1` 的 Special），并加「真的改到 ≥1 格」防空转断言（判据别用「两边相等」）。先例 `PlanetProgressiveEditTests.cpp` 的 `SeedMixed`。
- UniverseMap 第三颗行星（131072 世界 / `RenderOctreeDepth 12` / 半径 40000）进 PIE 卡 34 秒不是解压/网格化/读文件：`DecompressVoxelSave` 2.0–3.0 s，`FVoxelData::LoadFromSave` 36–43 s。约 33 秒在 `VoxelData.cpp:704-727` —— 存档把「与生成器相同的值」存成 `FVoxelValue::Special()` 哨兵，装填时逐哨兵体素调一次 `Generator->Get<FVoxelValue>()`。载荷 2,433,096 块 / 深度 13 / 解压后 882 MB（约 8600 块整块缓冲），折合每体素 ~100 ns。
- 修法（已生效）：`Config/DefaultEngine.ini` 的 `[ConsoleVariables]` 设 `voxel.data.StoreSpecialValueForGeneratorValuesInSaves=0`，再用控制台命令 `StellarEra.Planet.ResaveAll 0` 重存（读用旧设置、写前切新设置，插件要求存读一致）。`LoadMap` 从 36.16 s → 3.36 s，存档 144.8 MB → 145.5 MB（+0.5%）。`UVoxelDataTools::LoadFromSave(World, FVoxelUncompressedWorldSave)` 公开，可只把解压挪工作线程（装填因 `VoxelObjectArchive.cpp:8` 的 `check(IsInGameThread())` 必须游戏线程）；修好后异步只剩 0.75 s 收益，`StellarEra.Planet.BackgroundSaveLoad` 已在 2026-10-29 整套删除。
- 迁移旧存档次序不能乱：ini 给 1 → 进关卡（慢 36 s，此时摸到正确世界）→ 跑 `StellarEra.Planet.ResaveAll 0`（命令内部先切 CVar 再写）→ ini 改回 0。仓库里 `Content/Saves/PlanetVoxel/**` 仍是旧格式（145 MB LFS 资产不提交），新克隆必须走一遍。

## 蓝图与编辑器脚本

- 蓝图 `For Each Loop` 直接吃 `Get Attached Actors` 输出、循环体里 `Destroy Actor`，实测只销毁一半：4 个挂接 Actor 删了第 0、2 个，留下 1、3。挂接关系变化会让数组在遍历中缩短、索引前移跳元素，表现为「跑过但没清干净」，多次调用子 Actor 越积越多（本项目 3 盏灯变 4、5 盏）。修法：先 `Set <TArray<Actor> 变量> = Get Attached Actors` 再对变量遍历销毁。复现判据：连调两次重建，子 Actor 数量恒定。踩点是 `BP_VoxelPlanet.RebuildStarLights`。
- 纯蓝图无法在细节面板改值时自动 spawn Actor：① Construction Script 里 spawn 被引擎拒绝 —— `ULevel::SpawnActor` 在 `bIsRunningConstructionScript` 为真时返回 NULL（`LevelActor.cpp:504`），`AActor::ExecuteConstruction` 无条件置位（`ActorConstruction.cpp:892`）；② 编辑器世界里的已摆放 BP 不 Tick（实测 0 次，PIE 才有）。
- 上一条的修法：`BeginPlay` 自动重建 + 一个 `CallInEditor` 自定义事件（细节面板出现按钮）供编辑器态手动重建；重建要幂等（先清旧子 Actor 再生成，清理遍历数组副本）。`bCallInEditor` 是 `UK2Node_CustomEvent` 的 UPROPERTY，`BlueprintService.configure_node(..., "bCallInEditor", "true")` 可写。
- 按钮要落到指定分类不能用自定义事件（`UK2Node_CustomEvent` 没有 `Category` 字段，按钮永远在「默认」）：建函数图当按钮调自定义事件本体，再给函数入口写 MetaData —— `configure_node(bp, "<函数名>", "<K2Node_FunctionEntry 的 node_id>", "MetaData", "(Category=Planet,bCallInEditor=True)")`（走 `FProperty::ImportText_Direct`，结构体可部分导入）。`MetaData` 在 Python 里是 protected 读不回，验证往 Category 塞独特串再 `grep` 落盘 `.uasset`（FText 存 UTF-16）。
- 编辑器里只有两条 Python 路径会真正重跑 Construction Script：`EditorActorSubsystem.spawn_actor_from_class(...)`（新建实例必跑一遍）、`BlueprintService.compile_blueprint(bp)`（重编后所有已摆放实例各重跑一遍）。反例都不重跑：`actor.set_actor_location(...)`、`actor.set_editor_property(...)`、`EditorActorSubsystem.duplicate_actor(...)`——编辑器拖拽走 `PostEditMove → RerunConstructionScripts()`，Python 这些调用绕过了 `PostEditMove`。
- Python 调不到蓝图里定义的函数：`actor.refresh_light()` 报 `AttributeError: 'DirectionalLight' object has no attribute 'refresh_light'`。无头脚本里触发蓝图逻辑只能靠 spawn / 重编译 / 改属性，或在函数里临时插 `PrintString` 取证（日志落 `Saved/Logs/StellarEra.log` 的 `LogBlueprintUserMessages`，用 `grep -c` 数次数，别把 Python 自己打印的同名串算进去）。副作用：VibeUE python runner 会 `auto_save`，spawn 的 Actor 包直接落盘（返回里 `saved_packages`），测完销毁并查 `git status -- Content`。
- `AActor::bIsSpatiallyLoaded` 默认 true（`Actor.h`）。`UniverseMap` 是 World Partition 关卡，原有 Actor 都是 `spatial=False`，脚本 `spawn_actor_from_class` 出的新 Actor 是 `spatial=True`。后果很迷惑：外部 Actor 包确实写盘了、`WorldPartitionBlueprintLibrary` 里也确实有 descriptor（`ActorDescContainer` 扫 `__ExternalActors__` 目录建的），但关卡加载时那片空间没有已加载 cell，编辑器与 PIE 都看不到它，`save_current_level()` 还返回 True。
- 上一条判据：`unreal.WorldPartitionBlueprintLibrary.get_actor_descs_for_actors([a])[0].is_spatially_loaded`，或比对「落盘后重启，Actor 数对不对」。修法（C++ `SetIsSpatiallyLoaded()` 没暴露给 Python）：`a.set_editor_property("is_spatially_loaded", False)` 再 `level.save_current_level()`。孤儿清理：不在关卡 Actor 列表的包只在 descriptor 留幽灵，删 `Content/__ExternalActors__/<map>/xx/yy/*.uasset` 即可（先确认没被引用）。
- UE 5.8 细节面板会把每个 `UPROPERTY(VisibleAnywhere)` 组件**自己的属性分类**并进 Actor 细节（飞船会冒出整块 `Voxel Invoker` + SceneComponent 的物理/碰撞/光照/渲染/LOD…）。删掉该 UPROPERTY 的 `VisibleAnywhere`（只留 `BlueprintReadOnly`）后：关卡细节该分类消失；关卡组件树（细节面板顶部 Subobject 树）也不再列出该组件 → 关卡实例上没法逐实例调参；但蓝图编辑器「组件」面板仍列出可编辑（`BP_SpaceshipPawn` 四个 VoxelInvoker 都还在）。两者同一个 `CPF_Edit` 驱动，没有只隐藏细节保留关卡树的开关。2026-11-25 实测，`ASpaceshipPawn` 的 VoxelInvoker/LOD3/5/6 已按此改。
- `unreal.Color(r, g, b, a)` 的位置参数按 FColor 内存序 **B,G,R,A** 填：`unreal.Color(140, 166, 217, 255)` 实际得 r=217、g=166、b=140。repr 也按 b,g,r,a 字母序打印，容易看错。写颜色统一用关键字 `unreal.Color(r=..., g=..., b=..., a=255)`，设完立刻读回 `c.r/.g/.b` 写日志，别用 repr 判断（2026-10-24 想设冷蓝却设成暖橙，静默无报错）。
- `unreal.Rotator(a, b, c)` 位置参数是 **Roll, Pitch, Yaw**，不是 C++ 的 `FRotator(Pitch, Yaw, Roll)`。`unreal.Rotator(-35, 0, 0)` 实际是 Roll=-35，编辑器视口被滚歪（「相机是歪的、地平线倾斜」）。一律用关键字 `unreal.Rotator(roll=0.0, pitch=p, yaw=y)`，设完读回 `rot.roll/.pitch/.yaw`。**会持久化**：编辑器把视口相机（含 Roll）存进 Saved 配置，一次写错的 Roll=-35 之后每次启动都歪，改完必须读回 `rot.roll == 0`。用户恢复视角办法是选中 Actor 按 F。

## C++ 与 UHT

- UE 5.8 的 `UChildActorComponent` 三个 API 坑：头文件是 `#include "Components/ChildActorComponent.h"`，**没有** `Engine/ChildActorComponent.h`；`ChildActorClass` 是 private（`meta=(AllowPrivateAccess)` 只放行蓝图），写类走 `SetChildActorClass(TSubclassOf<AActor>)`、读用 `GetChildActorClass()`；`AActor::GetComponentsByClass` 在 C++ 不存在（只有蓝图包装 `K2_GetComponentsByClass`），用模板 `Actor->GetComponents<UChildActorComponent>(Arr)`（const 方法，能吃 `const AActor*`）。
- 附带：`UChildActorComponent` 默认**不**把 Owner 传给子 Actor，断言 `GetChildActor()->GetOwner() == 父 Actor` 会挂，要先 `SetChildActorOwnerOnCreation(true)`。
- `AVoxelPlanetActor::RebuildPlanet` 在类默认值对象上跑过一次后，`NewObject<UVoxelPlanetGenerator>(this, TEXT("VoxelPlanetGenerator"))` 在 `Default__BP_VoxelPlanet_C` 下留了同名子对象。此后每颗行星的 `VoxelPlanetGenerator`（outer 是 Actor）按名字解析 archetype（`UObjectArchetype.cpp:127` `FindObjectWithOuter(ArchetypeToSearch, Class, Name)`）命中 CDO 那个私有子对象，保存外部 Actor 包时 harvester 连带 harvest 原型（`PackageHarvester.cpp:616`），报 `Illegal reference to private object: '...Default__BP_VoxelPlanet_C:VoxelPlanetGenerator'`，**且 `Property: <unknown>`**（原型依赖没有属性链）。
- 上一条判断手法：`LogSavePackage: Warning: SavePackage Invalid Reference Diagnostics:` 打出 instigator 完整路径（`SavePackage2.cpp:890` 无条件打）。被引用者与引用者**同名**且 `Property: <unknown>` ⇒ 基本就是 archetype。修法（编辑器里、不重编）：CDO 上那个子对象 `obj.rename('StaleCDOGenerator')`，名字失配后 archetype 落回类 CDO，harvester 在 `PackageHarvester.cpp:617` 判等后跳过。改属性走不通（`VisibleAnywhere` = `Edit|EditConst`，Python 侧只读）。
- 存外部 Actor 包别用 `EditorAssetLibrary.save_loaded_asset`（外部 Actor 包不是 asset，报 "Asset is not registered"），用 `EditorLoadingAndSavingUtils.save_packages([pkg], False)`，pkg 取 `actor.get_outermost()`。主防线是代码里「没有世界就早退」；注意 CDO 序列化会把 `Transient` 属性也写进去（`PackageHarvester.cpp:638`），瞬态属性挡不住它跟着 BP 包一代代传下去。
- 模块合并（2026-10-31 地质并入 Planet）后出现过：`Intermediate/.../Inc/StellarEraPlanet/UHT/*.gen.cpp` 已是 `TEXT("/Script/StellarEraPlanet")`，但 `Binaries/Win64/UnrealEditor-StellarEraPlanet.dll` 的 mtime 更早（那次没链上）。运行中的二进制仍把 `UPlanetGeologyPreset` 注册在 `/Script/StellarEraGeology.*`，`[CoreRedirects]` 改写到不存在的新路径，`DA_Geology_Earth` 加载失败：`LogLinker: Warning: Unable to load DA_Geology_Earth ... because its class (PlanetGeologyPreset) does not exist`。编辑器症状是「资产拖不进 Details 属性槽」（显示 None，无报错）。
- 上一条判据（无头一行）：`unreal.<类名>.static_class()` 再 `unreal.SystemLibrary.get_path_name()`，看包名是旧还是新模块。注意 `unreal.load_class(None, '/Script/StellarEraPlanet.X')` 返回 `None`，而用旧路径调 `load_class` 返回真类对象——`LoadObject` 先 `FindObject` 命中旧路径就直接返回。修法：关编辑器 → dotnet 直调 UBT 重编 → 类落新路径。复验看 `grep -c "Unable to load"` 从 4 → 0。删掉的 `StellarEraCore` / `StellarEraGeology` 的 `UnrealEditor-*.dll` 会赖在 `Binaries/Win64/`（UBT 不清理，不在 `.uproject` 里所以不加载，但干扰判断）。
- `ADirectionalLight` 的构造函数把灯光组件**相对**旋转写死 `FRotator(-46, 0, 0)`（`Light.cpp:239`）并当 RootComponent。`SpawnActor<ADirectionalLight>(Loc, FRotator(-90,0,0))` 得到的 `GetActorForwardVector()` 是 −136°（−90 + −46）朝向，`SetActorRotation` 不会消掉相对旋转。2026-11-02 写恒星方向测试按 −90° 写死期望 (0,0,−1)，实测得 (0.719, 0, 0.695)。需要「某朝向的灯」时先 `SetActorRotation()` 再读回 `GetActorForwardVector()` 当期望，别从构造的 `FRotator` 推。`UPlanetAtmosphereComponent::ComputeSunDirection` 回退分支同样取 `-GetActorForwardVector()`。

## 光照与渲染

- `UCosmosSimulationSubsystem` 是 `UTickableWorldSubsystem`，在 `UWorld::Tick` **末尾**（`FTickableGameObject::TickObjects`）才把求解器结果写回天体 Actor，而组件的 `TickComponent` 在此之前跑。所以组件 Tick 里读 `GetComponentLocation()` 写进 MID 的永远是**上一帧**位置——同一机制已让三种不同症状各暴露一次：① 大气整层「在抖」（2026-11-04，MID `PlanetCenter` 与行星实际位置差 184,745 cm，行星 7.8 km/s、2.5 FPS 时一帧走 3.1 km）；② 大气壳边缘硬边（相机 `CameraPos` 同一坑）；③ 山体阴影/光影闪烁（2026-11-07，`ApplyPlanetShadow` 把行星球心写进光函数 MID，偏 163,110 cm ≈ 1.63 km、逐帧在 1.55~1.65 km 间跳，半影只有半径 1% = 200 m，晨昏线整片翻面）。
- 上一条修法：凡「描述会移动物体位置」的逐帧材质参数都别用组件 Tick 写 MID。有对应图元 → 材质里从渲染侧取（相机 `CameraPositionWS`、图元自身 `ObjectPositionWS`，`OriginType = EPositionOrigin::Absolute`）；没有对应图元（光函数、后期）→ 传 `世界位置 − 相机位置` 小向量，着色器里 `CameraPositionWS + 它` 重建（同帧内相减，CPU 慢的一帧自动抵消，实测残差 0.7~11 cm）。绝对坐标别直接传：float32 在 3e8 cm 处 ULP 已有 32 cm，慢一帧就是公里级。只有不随物体移动的量（半径、散射系数、云参数）才适合长期留在 MID。
- 改 `Shaders/PlanetClouds.ush` 后重跑 `StellarEra.BuildAtmosphereMaterial`、甚至 `unreal.MaterialEditingLibrary.recompile_material()`，画出来都是像素级一致的旧结果（引擎源码看似支持 `FMaterial::GetExpressionIncludesHash()` 算进 shader map id，实测不认）。解法：Custom 节点 Code 顶部写 `#define PLANET_CLOUDS_VERSION N`，每次改 `.ush` 就把 N 加一（Code 打哈希，必然重编）。版本号在 `PlanetAtmosphereMaterialBuilder.cpp` 的 `AtmosphereHLSL` 字符串里，改动连带一次 C++ 重编。`.ush` 由 `HLSLMaterialTranslator` 展开成 `#include`，插在 `CustomExpressionN` 函数体**之前**（函数能定义但看不见 Custom 节点输入，每个依赖量都要显式传参）。判据：「改完 .ush 画面一点没变」先怀疑缓存。

## 大气与水面

- 2026-11-04 更新：`PlanetCenter` **已不是 MID 参数** —— 材质改接 `ObjectPositionWS`（绝对世界坐标），C++ 不再每帧写（原因见上「光照与渲染」的 MID 慢一帧）。但 `SunDirection0..3` 仍是 MID 参数，编辑器预览照样要靠 `RefreshAtmosphereGeometry()` 补写。
- `UPlanetAtmosphereComponent` 编辑器视口里 `TickComponent` 不执行（构造函数已设 `bTickInEditor = true`，实测照旧不跑：行星摆 `y = 1e8` 时 `PlanetCenter` 读到 `(0,0,0)`、`CloudDrift` 停在 0）。材质整条 ray march 以 `PlanetCenter` 为原点，原点落在行星外 → 球面求交全落空，大气与云整层不画**且一条日志都不报**（表现为「壳在、缩放对、参数写了就是看不见」）。验证：临时把壳材质换成 `/Engine/EngineDebugMaterials/DebugMeshMaterial`，壳画成一个大球即说明几何没问题、是材质输出为 0。2026-11-02 合入体积云时分支上行星恰在原点没暴露，master 改到 `y = 1e8` 后云与大气全没。修法：别只依赖 Tick，在 `RefreshAtmosphereGeometry()`（OnRegister / BeginPlay / 半径变化必执行）里也写一次。
- 多恒星下行星盘面上的**柔和、近直、像折痕**的带子，来自大气材质里**每颗恒星各自的晨昏线**（`Shaders/PlanetClouds.ush` 里被 `M_PlanetAtmosphere` Custom 节点展开的 `CloudAtmosphereRaymarch`），不是三方向光叠加出错、也不是水面或地形。2026-11-04 用户用 PIE 截图问「像不像大气重叠」时我先答「是水面」，两天后发现水早在 `6a9d13f` 就关了、地形也没生成（HUD `Mesh tasks remaining: 15970`），盘面其实是空的大气壳。
- 晨昏线已修（2026-11-04，`PLANET_CLOUDS_VERSION 9`）：旧写法每采样点对每颗星单独算几何本影 `if (BS < 0.0) SunVis = smoothstep(PlanetRadius * 0.99, PlanetRadius * 1.01, DPerp);`（过渡仅 ±1% 半径，就是一条切线）。新写法 `SinSunElevation = BS / max(RLen, 1.0)`，`SunVis = smoothstep(-0.26, 0.02, SinSunElevation)`（约 −15° .. +1°，`PlanetClouds.ush:287-308`）。太阳高于该点地平线时几何上不可能被行星本体遮挡，故本影只在仰角淡出覆盖的那半边开火，删掉不丢遮挡；真实天空落山后还亮 ~15° 是多次散射，单次散射只能手工补回。不能改宽成 `max(本影, 黄昏)`：晨昏线上 `BS<0` 使 `DPerp≈R`、`smoothstep` 恰好返回 0.5，`max()` 永远取不到黄昏项，实测改完逐像素不变。
- 三颗星辐亮度差很大（`SunRadiance0`≈(1,0.94,0.78)、`SunRadiance1`≈(0.4,0.25,0.10) 暗橙、`SunRadiance2`≈(2.45,2.56,2.67) 亮蓝白），明暗台阶同时是**色相台阶**，更显眼。验证（Editor world，1 分钟）：隐藏全部 1760 个 `VoxelProceduralMeshComponent`、`CloudCoverage=0`、相机放 `planet + dir * 6e6`（40 km）看向行星中心；把大气 MID 的 `SunCount` 在 3/2 间切，折痕随 SunCount 出现/消失；相机方位角 45°→30°，折痕从盘心移到约 0.12 R 处（跟着晨昏线走，不跟屏幕走）。判定等式：相机方位角与某颗星方位角相差 90° 时那颗星晨昏线穿过盘心（2026-11-04 实测 `SunDirection2` 方位 −45°、相机 45°，折痕恰在盘心）。
- 验证修没修好用剖面不用肉眼：亮面横切一条线取相邻像素梯度，修前折痕处梯度先压到 ~0 再突然跳 +4.0，修后连续（+0.33），截图在 `Saved/VibeUE/Captures/` 的 `capture-editor-20261104-230802-379`（旧）与 `...232203-266`（新）。另 `CloudLight = max(CloudLight, CLOUD_AMBIENT)` 只对 `s == 0` 生效（`PlanetClouds.ush:322`），云在多恒星下每颗星处理不对称，星序一变云环境光行为会跳。
- `M_PlanetWater` 的 Custom 节点用 `thickness = SceneDepth - PixelDepth` 决定水色与不透明度（`Source/StellarEraPlanet/Src/Water/PlanetWaterMaterialBuilder.cpp:59-73`，`DepthFadeDistance=400 cm`、`MaxOpacity=0.85`、`ShallowOpacity=0.35`）。场景深度里有没有地形直接决定深浅：块已渲染 → thickness ≈ 水层厚度 → 浅色半透明；块没生成 → 背后是天空/远平面 → thickness 巨大 → `depthFactor=1` → DeepColor、0.85 不透明。所以行星还在生成时（HUD `Mesh tasks remaining` 上万）从轨道看是一颗整片深蓝的球，已生成与未生成区块交界投影成**直边/折线**，像「折痕」。
- **更正（2026-11-04 晚）**：上述机制成立，但当时那两条「折痕」不是水——水体已在 `6a9d13f` 关掉、地形也没生成，用户看到的是大气壳上的多恒星晨昏线（见上文）。别把两件事混为一谈。编辑器复现：`DA_Terrain_Earth.bEnableWater=True`（内存改，别存）→ `AVoxelPlanetActor::ReloadGeology()`（BlueprintCallable，Python 可调）重建水面，再 `set_visibility(False)` 隐藏部分 `VoxelProceduralMeshComponent`，水面立刻按区块深浅分块。根治方向：把水深在构建期烘进顶点属性，别读场景深度。看到「大片蓝色/深浅分块的直线边界」先看 HUD 任务数，别查大气。

## 飞船与几何指示物

- `BP_SpaceshipPawn` 的 `Hull` 就是根组件，轴心正好在船体几何中心。包围盒实测（`mesh.get_bounding_box()`，厘米）：`min (-2754.7, -4133.0, -996.0)`、`max (2754.7, 4133.0, 996.0)` → ±27.5 × ±41.3 × ±10.0 米。
- 所以任何「从飞船 Actor 原点 / 0,0,0 长出去」的指示物（箭头、光环、射线）起点都在船体内部。20 米的箭头整根埋进去，PIE 截图上橙色像素 **0**；拉到 60 米也只从船腹戳出 50 米，而追尾相机在上方俯视 24°、船体 83×55 米的投影把那片区域整个盖住。要它自己露头长度得超过最长半轴 41.3 米且相机恰能看到船底——实际做不到。
- 解法：材质关掉 **Disable Depth Test**，像 HUD 一样画在船体之上。现成：`/Game/Code/Planet/Materials/M_PlanetGhostOverlay`（`M_PlanetGhost` 的副本，`blend_mode=BLEND_TRANSLUCENT`、`shading_model=MSM_UNLIT`、`two_sided=True`），`UMaterial.get_editor_property("disable_depth_test")` 可读可写。
- 顺带坑：挂在根组件下的子组件，任何一次 `SetVisibility(false, bPropagateToChildren=true)`（比如藏船体）都会把子组件 `bVisible` 一起清成 false；组件若缓存「上次设的可见性」再据此早退，就会永久失联。别缓存，每次直接 `SetVisibility`（它内部会判等）。

- 画面被一条水平直线切成上下两半、错开一帧（编辑器里一转视角就有，**不 Play、纯转视口也有**），但逐帧扫 QQ 录屏 653 帧（含原生 1918×1026）一条撕裂线都找不到——因为录制读的是 DWM 合成后的完整缓冲。本机 i9-9980HK + GTX 1650 + Intel UHD 630，内屏 BOE099C 挂核显、UE 用 `Chosen D3D12 Adapter Id = 0` 走独显渲染。根因是 Windows **MPO（Multi-Plane Overlay）**：DWM 把应用交换链当独立硬件平面直接交显示控制器扫描，配合独显渲染→核显扫描的跨显卡拷贝，扫描在拷贝完成前开始（上半旧帧下半新帧）；VSync 无效（它同步渲染卡上的 present 队列，跨卡拷贝在其下游）。
