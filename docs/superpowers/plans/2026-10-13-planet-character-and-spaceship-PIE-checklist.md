## 2. 逐条核对

### A. 球面行走与相机（Task 1 + Task 2）

- [ ] 1. 视口里能看到一颗球体行星，球面上站着一个角色。
- [ ] 2. 角色**没有**掉进球体内部 —— 它停在表面上方不动。若缓慢下陷，检查
       `VoxelInvoker->bUseForCollisions` 是否为 true、行星 Actor 的 `bEnableCollisions`。
- [ ] 3. 角色脚下能看到碰撞体（控制台输入 `show Collision` 切换显示）。
- [ ] 4. 按 `W` 角色向远离相机的方向走；`S` 反向；`A` / `D` 左右横移。
- [ ] 5. 一直按 `W` 走，角色能**绕球走一整圈**；走到球的「另一面」时角色仍然直立
       （脚朝球心），没有倒挂或侧躺。
- [ ] 6. **走到球体背面（相对世界 Z 轴「下方」）时，按住右键左右移动仍然是水平环绕，画面不翻滚。**
       这是整个计划里最容易失败的一条；若失败说明相机枢轴没生效。
- [ ] 7. 按 `Space` 角色跳起并落回地面，不穿模。
- [ ] 8. 按住 `LeftShift` 行走速度明显变快。
- [ ] 9. Output Log 里不出现 `InputComponent 不是 UEnhancedInputComponent`。

### B. 飞船（Task 3）

- [ ] 10. 能看到一艘飞船停在球面上方。**机身 up 方向背离球心（机腹朝球面）**，
        不是朝球心 —— 计划原文这里写反了，以代码为准。
        ⚠️ 飞船生成在行星 **+Y 赤道方向**，角色在 **+Z 北极**，两者相距约 **157 米**
        （球半径 100 m，90° 圆弧）。按 `LeftShift` 冲刺约 13 秒能走到；
        也可以直接跳到下面第 11 条。
- [ ] 11. 控制台输入 `DebugPossessShip`，视角切到飞船。
- [ ] 12. 按 `W` 飞船加速前进；松手后平滑减速停下（不是立刻停）。
- [ ] 13. **快速甩一下鼠标，飞船开始转，松手后还会继续转一小会儿再停。**
        这是角速度惯性的验收点；若松手立刻停，说明 `MouseImpulseScale` 或 `AngularDamping` 没生效。
- [ ] 14. 按 `D` / `A` 机身横滚；松开后机身**缓慢自动回正**。
- [ ] 15. 按 `Space` / `LeftControl` 上升 / 下降。
- [ ] 16. 用 `W` 直冲行星表面，飞船**被挡在球面外**，不会穿进球体。
- [ ] 17. Output Log 里不出现 ensure 或 `LogVoxel` 的 Error。

### C. 登船 / 离船（Task 4）

⚠️ **先用 `DebugPossessShip` 切回角色再开始这一段。** `DebugPossessShip` 是往返开关：
在船里就 possess 场景里的第一只角色，否则 possess 最近的飞船。

- [ ] 18. 用 WASD 走到飞船旁，屏幕上出现黄色 `按 E 登船`。
- [ ] 19. 走远后提示消失。
- [ ] 20. 按 `E`：角色消失，视角切到飞船的追尾相机。
- [ ] 21. 飞起来后按 `E` **没有反应**（空中不能下船）。
- [ ] 22. 飞回球面、减速停稳，屏幕出现 `按 E 离船`。
- [ ] 23. 按 `E`：角色出现在飞船**旁边**（不是船里），可以继续用 WASD 行走。
- [ ] 24. 重复登船/离船 3 次，不出现角色卡在船里、相机错乱或 ensure。
- [ ] 25. 离船后角色不会掉穿地面。

> **注意**：`DebugPossessShip` 不会登记「登船角色」，所以用它进飞船后**永远不会**出现
> `按 E 离船` 提示 —— 这是有意为之（提示只在按 E 真的有效时才出现）。
> 要验登船/离船流程，请走上面第 18–25 条的真实 E 流程。

### D. 模型（Task 5）

- [ ] 26. 角色显示为 Pomni 模型而不是立方体，站在球面上。
- [ ] 27. 模型朝向正确 —— 面朝角色的前进方向，不是侧躺或倒立。
- [ ] 28. 模型大小合理 —— 大约两个人高，不是蚂蚁也不是巨人。
- [ ] 29. 飞船显示为航天飞机模型而不是立方体，大小与角色比例协调。
- [ ] 30. Output Log 里**不出现** `找不到角色模型` / `找不到飞船模型` 的 Warning。
- [ ] 31. 重新过一遍第 18–25 条，确认换模型没有破坏登船/离船流程。

## 4. 已知怪癖与调参说明

**鼠标灵敏度偏快。** Enhanced Input 绕过 `AxisConfig` 的灵敏度设置，用的是原始像素增量。
`LookSensitivity` 当前 1.2，体感偏快约 7 倍。觉得太快就告诉我，改一个数即可。

**走路时抬头/低头会略微变慢。** `Move` 把直线速度按 `cos(pitch)` 缩放（`PlanetCharacter.cpp`），
所以镜头俯仰到极限时前进会慢一点。这是有意的手感选择，不是 bug；不喜欢可以去掉。

**走近飞船时相机可能弹跳一下。** 飞船根部的 300 cm 碰撞球挡 `ECC_Camera` 通道，
角色自己的弹簧臂撞上它会被推近。纯观感问题，不影响功能。

**模型朝向/缩放的调节量是编译期默认值，PIE 里改不动。** `Character|Mesh` 下的
`Mesh Relative Rotation` / `Mesh Scale` 是在 C++ 构造函数里读一次就定死的，而且角色和飞船
都是 GameMode 在运行时生成的（不是关卡里摆好的实例），所以**在细节面板里改这两个值不会有
任何反应** —— 这是实现上的取舍，不是面板坏了。

调参路径只有两条：**改 `PlanetCharacter.cpp` / `SpaceshipPawn.cpp` 里的默认值 → 重编译
（约 20 秒）→ 再 PIE**；或者自己建 Blueprint 子类去存（那还要顺带改 GameMode 的
`DefaultPawnClass`，比改一个数麻烦）。计划原文说「不需要重编译」是不准确的，以此处为准。

**但换网格是真能实时改的。** 在 PIE 里选中角色 → `Mesh` 组件 → 换 `Skeletal Mesh`，
立刻就能看到效果。所以下面第 0 节那个「角色模型是不是 `Object_14`」的问题，
照原样在 PIE 里试就能定下来。

**飞船离角色出生点约 157 米。** 想改的话，`AStellarEraGameMode` 的 `ShipSpawnDirection`
默认是 `(0,1,0)`（+Y 赤道）；改成 `(0,0,1)` 就会生成在角色头顶的北极方向。

**屏幕提示在打包后的正式版里不会出现。** `按 E 登船` / `按 E 离船` 走的是
`GEngine->AddOnScreenDebugMessage`，它在 Shipping / Test 构建里被编译掉。spec §5.5
明确允许这种做法，所以这是**已知限制而非缺陷**：本清单的第 18、22 条只在编辑器里有效，
打包版要显示提示得换成 HUD / UMG。
