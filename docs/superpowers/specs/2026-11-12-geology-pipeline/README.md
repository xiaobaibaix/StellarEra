# 地质生成流水线（设计草案）

> 状态：**草案，供讨论**。定稿后按项目约定并入 `docs/superpowers/specs/2026-11-12-…-design.md`。
> 上游调研：`docs/research/2026-11-11-geology-driven-terrain-analysis.md`
> 目标一句话：**矿不是撒出来的，是长出来的。**

## 为什么重构

现状 `SamplePlanetGeologyPlacement` 按带权深度随机撒点，矿与地形没有任何因果关系：
火山不带硫磺、盆地不带盐、河谷下游不带砂金，任何深度都可能出现任何矿。

要的是这条链：**活火山 → 硫磺结壳 → 挖到硫磺；干旱封闭盆地 → 盐滩 → 挖到岩盐/钾盐**。
因果一旦成立，矿的分布就天然有规律，玩家也就能靠「读地貌」来预判。

## 一句话架构

```
烘焙期（每颗星一次，后台线程）
  标准球体 → 逐阶段叠加地形特征 → 每阶段顺手撒本阶段的矿
  ↓ 产出：球面场(cubemap) + 三维基元集(BVH) + 径向剖面表
只读地质模型（冻结，可跨线程共享）
  ↓ 求值期（每体素，纯函数，任意 LOD）
  查表 → 密度 / 材质 → 体素网格化
```

**层不知道体素插件，体素插件不知道层。** 中间只隔一个只读模型，
所以「看到的线索」和「挖到的矿」永远一致，仪器扫描、调试可视化、测试都查同一个模型。

## 三个必须先纠正的概念

1. **「最终密度场」不能物化成数组。**
   R=500 体素时全三维场是 5.2×10⁸ 个体素，按 8 字节算是 4.2 GB，还没有算材质。
   所以流水线产出的是**场（二维图 + 基元集 + 径向表）**，体素值在网格化时按需求值。
   用户原话「跑完流水线后形成最终的密度场和材质分布场」，准确说法是「形成**可求值**的模型」。

2. **横向尺寸不能按行星半径等比缩放。**
   这颗星是地球的 1/12742，等比之后每个矿体都只有 0.1 个体素。
   竖向按比例、横向取 `max(等比, 最小可辨)`，见 `00-pipeline.md` 的分辨率预算。

3. **「密度含量」是三个不同量纲，不能混用：**
   - 背景含量 clarke（元素在地壳的平均丰度，ppm/%）→ 阶段 1 的径向表
   - 品位 grade（这一个矿体有多富，按矿种自己的刻度）→ 材质 B 通道
   - 规模 / 面密度（一颗星上有几个、每 km² 几个）→ 规则的撒点参数
   三者混成一个「密度」，规则表就再也调不动了。见 `minerals/README.md`。

4. **板块 ≠ 大陆。**（2026-11-12 补）
   一块板块可以同时有陆有洋（欧亚板块既有喜马拉雅也有西太平洋边缘海），也可以是纯洋（太平洋板块）。
   `PlateId` 决定边界在哪，`ContinentalMask` 决定陆海格局，两者独立生成、各自冻结。
   焊死的话，被动陆缘、陆表海、陆内盆地全部失去输入。

5. **噪声能做质感，做不了格局。**（2026-11-12 补）
   零均值噪声处处平均，用它当主控只会得到陆海碎斑。大陆必须由**显式陆核**（高斯团 + 平滑并集）铺出来，
   噪声只负责揉皱轮廓、加内部起伏。判别指标是「大圆穿越海平面次数 ≤ 6–10」。
   **同一条规律在阶段 3 再次成立**：山不能靠全域 fBm 铺（那只会得到满地疙瘩，没有平原也没有山），
   必须由**山带遮蔽权重**（边界类型 × 距离剖面 × 沿走向分段）来选位置，噪声只负责山带的细节与脊线。

| 词 | 含义 |
|---|---|
| 阶段 Stage | 流水线的一环，按地质成因排序，后阶段只读前阶段产物 |
| 黑板 Blackboard | 阶段之间的数据总线。**实现上是类型化结构体 `FPlanetBakeFields`，不是 FName→Variant 的字典**，见 `20-architecture.md` §1.2 |
| 球面场 SphereField | 6 面 × N² 的 cubemap，按方向查表 |

| 贡献器 Contributor | 冻结后的只读求值器，线程安全 |
| 线索 Clue | 写进材质的视觉信号（蚀变色、铁帽、盐壳、硫磺黄） |
