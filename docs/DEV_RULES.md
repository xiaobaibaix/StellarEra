# 开发规范（项目级，随仓库入库）

> 这份文件是 `~/.claude/CLAUDE.md` 全局约定的项目镜像，外加项目里踩过的补充。
> 冲突时以本文件与根 `CLAUDE.md` 的明确条款为准。

## 标识符一律驼峰，面板显示名也不许带空格/下划线/括号

- `CreateDefaultSubobject` 的字符串名、组件 UPROPERTY 变量名、蓝图组件变量名，只用字母数字：`SunLightDriver`、`PlanetSkyLight`、`LODInvoker`。
- 细节面板会把 C++ 变量名的驼峰自动拆成「Sun Light Driver (SunLightDriver)」——这是噪声。凡是会显示在面板上的新属性，一律补 `meta = (DisplayName = "SunLightDriver")`，让显示名与变量名逐字一致。
- 这条对 C++ 属性、蓝图变量、组件名同等生效。

## UE 编译：自己关编辑器，不要每次问

需要编译 C++ 而编辑器开着（Live Coding 锁 DLL）时：

- 先保存需要保存的内容（关卡 / 资产脏包），
- 自己退出编辑器（编辑器内控制台 `quit_editor`，或结束进程），
- 编译完再告知结果。

不要每轮都问"要我关吗"。只有「保存会覆盖用户明确不想要的改动」时才问一次。

## 改完必须自己编译并跑出来验证

每次改动完成后，不许停在"编译通过"：

- 关编辑器 → 编译 → 重新打开 → 触发重建/运行 → **截图或读日志确认实际效果**。
- 只有亲眼看到结果（截图 / 日志证据）才可以说"好了"；看不到就明说"我没验证到"。
- 验证失败（编译错、运行报错、画面不对）时自己继续查，不要交回给用户。

## 给细节面板 / UI 添加项时必须检查表现

- **加完要实际看面板**：确认属性真的出现、只有一份、命名与语言一致（不出现中英两份、不出现重复的组件分区）。
- **脚本加组件后立即校验唯一性**：用 `BlueprintService.list_components` 数一遍；出现 `X` 与 `X1` 说明命名冲突，用 `SubobjectDataSubsystem.rename_subobject` 改回。
- **按名删除会一次删光**：`remove_component(bp, "X")` 对多个同名组件会全部删掉，删前先数、删后重新添加并再校验。
- 面板里"多出来的一栏"和"缺一栏"同样算缺陷，不能只看编译是否通过。
